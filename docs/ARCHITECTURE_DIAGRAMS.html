01 · System

End-to-end flow

A customer folder is ingested into one Dossier. The engine scores it with the deterministic rules and the LLM graph in parallel, reconciles them into a confidence, then routes: confident cases are stored and served; unsure cases (or a sanctions hit) go to the human queue.

03 · Ingestion

Ingestion, step by step — what goes in, what comes out of each

Ingestion has one job: turn a pile of mixed files (from a folder, an upload, or pasted text) into one typed Dossier, then distil that Dossier into the compact fact-strings each LLM analyst actually reads. Three entry points, five parsers, one object, three prompts.

Stage 1 · raw file → typed field

Each input stream has its own parser and its own output type. Missing files don't crash ingestion — they fall back to a safe empty default, which is what makes a half-complete customer still scorable.

InputParserComes out asWhat it is
kyc.jsonjson.loadskyc: dict Identity: name, DOB, nationality, occupation, kyc_complete, whether an ID doc exists.
account.jsonjson.loadsprofile: dict (+ customer_id) Account facts: type, tenure (days), balance, PEP flag, country. customer_id is split off as the dossier key.
transactions.csvcsv.DictReader → Txntransactions: list[Txn] One row → one typed Txn; amounts parsed as Decimal (never float) so money math is exact.
screening.jsonjson.loadsscreening: dict Sanctions hits, pep_confirmed, adverse-media list. Empty-safe default if absent.
*.txt (all)glob + readdocuments: list{name, kind, text} Every unstructured file — ID OCR, RM notes, news articles, emails — kept verbatim for the LLM to read.
_meta.jsonjson.loadsmeta: dict Generator bookkeeping (expected band, injected typology) — used by self-checks, not by scoring.
Stage 2 · Dossier → the exact text each LLM sees

The analysts don't get the whole Dossier — each builder emits a short, calibrated fact-string and appends only the unstructured documents relevant to its domain. This is precisely "what data goes inside" each LLM call.

BuilderStructured facts it emitsUnstructured docs appended
_kyc_text() → KYC analyst nationality/country, occupation, PEP, account age, kyc_complete, id-doc present? id_document.txt (ID OCR) + rm_notes.txt
_txn_text() → Transactions analyst count, total credits/debits, cash-in, distinct counterparty-countries, + a typology watch-list prompt correspondence.txt (emails that explain or expose transfers)
_screening_text() → Screening analyst sanctions hit names, pep_confirmed, adverse-media headlines adverse_media_*.txt (the full article text, not just the headline)

Missing files degrade to safe defaults (empty dict / list) — ingestion never throws, so a customer with only a KYC file and no transactions still produces a valid Dossier. Code: data/loaders.py (load_customer, _txns_from_csv, dossier_from_files, parse_pasted); builders in ai/orchestrator.py.

04 · Orchestration

Five LLM calls, sequenced as a LangGraph

Not one prompt — a graph. Three analysts run in parallel (fan-out), a senior synthesizer correlates them, an adversarial QA reviewer re-checks the score, and a deterministic step packages the result. Recent human corrections are injected into the synthesizer as few-shot examples.

flowchart TD
  S((START)):::se --> KA["① KYC analyst
LLM · risk_level + signals"]:::llm
  S --> TA["② Transactions analyst
LLM · hunts structuring/layering/
round-trip/dormant-spike"]:::llm
  S --> SA["③ Screening analyst
LLM · sanctions · PEP · adverse media"]:::llm
  FB["👤 human few-shot examples"]:::human -. "injected" .-> SY
  KA --> SY["④ synthesize
LLM · correlate 3 domains,
weigh reinforcement, self-confidence 0–1"]:::llm
  TA --> SY
  SA --> SY
  SY --> VF["⑤ verify — QA reviewer
LLM · adversarially check & correct the score"]:::llm
  VF --> FN["finalize
deterministic — no LLM
QA score wins; schema-validated"]:::rules
  FN --> CF{{"composite confidence =
min(self, node-agreement, verifier, err-penalty)"}}:::gate

05 · Reliability

The never-fails cascade

The LLM boundary can never blank out or raise to the caller. It tries the best path available and falls through to cheaper, always-available ones — degrading gracefully instead of failing.

flowchart LR
  A["crosscheck(d, rules)"]:::llm --> C{"cache hit?"}:::gate
  C -->|yes| HIT["return cached
(instant)"]:::store
  C -->|no| M{"multi-step
enabled?"}:::gate
  M -->|yes| G["5-node graph"]:::llm
  G -->|ok| P1["path = rules+graph"]:::llm
  G -->|node/graph fails| SG["single provider.complete()
instructor · retry + backoff"]:::llm
  M -->|no| SG
  SG -->|ok| P2["path = rules+llm"]:::llm
  SG -->|no API key| RO["rules-only finding"]:::rules
  SG -->|hard error| SIM["simulated finding"]:::rules
  P1 --> OUT["(finding, meta.path)"]:::store
  P2 --> OUT
  RO --> OUT
  SIM --> OUT

06 · Human-in-the-loop

Confidence gate & the teach-the-model loop

The composite confidence and the one hard rail decide the exit. Confident cases auto-dispose; unsure ones become a real message on a Redis queue. The reviewer's correct score is stored and fed back as a few-shot example — so the human improves exactly the cases the model was least sure about.

+ composite confidence"]:::llm --> KILL{"sanctions

(next runs)"]:::llm
